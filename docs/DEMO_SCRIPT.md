# สคริปต์สาธิตระบบต่อหน้าอาจารย์

เดินตามลำดับการใช้งานจริง ครบทั้ง 4 บทบาท ใช้เวลาประมาณ 12–15 นาที

เส้นเรื่องคือ **ตามของหนึ่งชิ้น ตั้งแต่มีคนอยากบริจาค จนถึงมือผู้ประสบภัย**
ไม่ใช่การไล่เปิดทีละหน้า เพราะการเล่าเป็นเรื่องเดียวจะเห็นภาพว่าระบบเชื่อมกันยังไง

เว็บ https://disaster-relief-rho.vercel.app

## ฉากที่ 1 — ผู้ใช้ทั่วไป ไม่ต้องล็อกอิน

> เปิดหน้าเว็บโดยยังไม่ล็อกอิน เพื่อให้เห็นว่าคนทั่วไปเข้ามาเจออะไร

### 1.1 หน้าแรก

เปิด `/`

**พูดว่า** หน้านี้ไม่ต้องล็อกอิน คนทั่วไปเห็นได้เลยว่าตอนนี้ศูนย์ขาดอะไรบ้าง
ตัวเลขนี้ดึงจากฐานข้อมูลจริง ไม่ได้พิมพ์ไว้

**ชี้ให้ดู** การ์ดสรุปของที่ขาด และปุ่มทางเลือก 3 ทาง (สมัครอาสา / ขอความช่วยเหลือ / แจ้งบริจาค)

### 1.2 แจ้งความประสงค์บริจาค

กด **ร่วมบริจาค** → `/pledge`

**กรอกจริงต่อหน้าอาจารย์**

```
ชื่อ          คุณสมศักดิ์ ใจบุญ
เบอร์         081-234-5678
ตำบล/จังหวัด  ท่าศาลา / นครศรีธรรมราช
สิ่งของ       ข้าวสารฮาลาล 5 กก.
หมวดหมู่      อาหาร
ข้อกำหนดอาหาร ฮาลาล          ← จุดสำคัญ อย่าลืมเลือก
จำนวน/หน่วย   20 ถุง
```

**พูดว่า** ช่องข้อกำหนดด้านอาหารสำคัญมาก เพราะถ้าจ่ายของผิดประเภทออกไป
ของถึงมือแต่กินไม่ได้ เท่ากับสูญเปล่า เดี๋ยวจะให้ดูว่าระบบกันเรื่องนี้ยังไง

กดส่ง → ขึ้นข้อความว่าส่งแล้ว รอเจ้าหน้าที่ติดต่อกลับ

### 1.3 ขอความช่วยเหลือ

กลับหน้าแรก → **ขอความช่วยเหลือ** → `/help-request`

```
ชื่อ          คุณฟาติมะห์ ยูโซ๊ะ
เบอร์         089-111-2233
ตำบล/จังหวัด  คลองแห / สงขลา
ศูนย์พักพิง    ศูนย์พักพิงวัดคลองแห     ← ต้องเลือกศูนย์นี้
สิ่งของ       ข้าวสารฮาลาล
หมวดหมู่      อาหาร
ข้อกำหนดอาหาร ฮาลาล
จำนวน         10
ความเร่งด่วน   สูง
```

**ชี้ให้ดู** พอเปลี่ยนหมวดหมู่เป็นอย่างอื่นที่ไม่ใช่อาหาร ช่องข้อกำหนดอาหารจะหายไป
เพราะถามเรื่องฮาลาลกับผ้าห่มไม่มีความหมาย

**ต้องเลือกศูนย์พักพิงวัดคลองแห** เพราะฉากที่ 3 จะล็อกอินเป็นอาสาสมัครของศูนย์นี้

### 1.4 สมัครอาสาสมัคร

กลับหน้าแรก → **สมัครอาสาสมัคร** → `/register`

**ชี้ให้ดู** ฟอร์มมีไอคอนนำทุกช่อง เบอร์โทรใส่ขีดให้อัตโนมัติและล็อก 10 หลัก
และมีช่องอัปโหลดรูปยืนยันตัวตนซึ่งเป็นช่องไม่บังคับ

**ถ้าเวลาไม่พอ** ไม่ต้องกดสมัครจริง แค่โชว์ฟอร์มแล้วอธิบาย
เพราะบัญชีใหม่ต้องยืนยันอีเมลก่อนถึงจะล็อกอินได้ (ดูหัวข้อความเสี่ยง)

## ฉากที่ 2 — เจ้าหน้าที่และผู้ดูแล

> สลับไปหน้าต่างที่ล็อกอิน `adminTest` ไว้แล้ว

### 2.1 หน้าสรุปภาพรวม

เปิด `/`

**ชี้ให้ดู** ตัวเลข 4 การ์ดด้านบน กราฟสัดส่วนของในคลัง และกล่อง "ต้องดำเนินการ"

**พูดถึงแถวสีแดง** หมดอายุแล้ว ระบบแยกให้เห็นชัดว่าของหมดอายุค้างอยู่กี่ล็อตกี่ชิ้น
ไม่ใช่รวมกับของที่ใกล้หมดอายุ เพราะสองอย่างนี้ต้องจัดการคนละแบบ

กดแถวนั้น → พาไปหน้าคลังที่กรองเฉพาะของหมดอายุไว้ให้แล้ว

### 2.2 ตรวจคำร้องบริจาคที่เพิ่งกรอก

เปิด `/pledges`

**ชี้ให้ดู** คำร้องของคุณสมศักดิ์ที่เพิ่งกรอกเมื่อครู่ โผล่มาแล้ว พร้อมป้ายฮาลาล

กด **ยืนยัน** → ระบบแปลงเป็นล็อตของในคลังให้อัตโนมัติ

**พูดว่า** ตรงนี้คือจุดที่ข้อมูลจากคนทั่วไปถูกตรวจก่อนเข้าระบบจริง
คนนอกเขียนลงตารางจริงไม่ได้ ต้องผ่านเจ้าหน้าที่เสมอ

### 2.3 ของเข้าคลังแล้ว และใบรับของ

เปิด `/donations` → เห็นล็อตใหม่ที่เพิ่งอนุมัติ

กดเข้าไปดู → กด **ใบรับของ**

**ชี้ให้ดู** ใบรับของแสดงชื่อผู้บริจาค ที่อยู่ ข้อกำหนดด้านอาหาร และพิมพ์ได้จริง
กด Ctrl+P ให้ดูตัวอย่างก่อนพิมพ์

**พูดว่า** ถ้าผู้บริจาคเลือกไม่ประสงค์ออกนาม ใบนี้จะปิดทั้งชื่อ เบอร์ และที่อยู่

### 2.4 ทะเบียนผู้บริจาค

เปิด `/donors`

**ชี้ให้ดู** คุณสมศักดิ์ถูกเพิ่มเข้าทะเบียนอัตโนมัติพร้อมที่อยู่ ไม่ต้องกรอกซ้ำ
ลองใช้ตัวกรองจังหวัด เลือกนครศรีธรรมราช จะเจอ

กด **ดาวน์โหลด CSV** ให้ดู แล้วบอกว่าผู้ไม่ประสงค์ออกนามถูกปิดข้อมูลในไฟล์ด้วย
ไม่ใช่ปิดแค่บนหน้าจอ

### 2.5 ตรวจคำขอความช่วยเหลือ

เปิด `/help-requests`

**ชี้ให้ดู** คำขอของคุณฟาติมะห์ที่เพิ่งกรอก พร้อมป้ายฮาลาลและที่อยู่

กด **ยืนยัน** → กลายเป็นคำขอจริงในระบบ

### 2.6 คลังสินค้า

เปิด `/inventory`

**ชี้ให้ดู**
- ยอดคงเหลือแยกตามศูนย์และหมวดหมู่
- ตัวกรองข้อกำหนดด้านอาหาร
- ของที่หมดอายุแล้วมีเครื่องหมายกำกับ
- เรียงคอลัมน์ได้ และส่งออก CSV ได้

### 2.7 จัดสรรของ — จุดที่ต้องเน้นที่สุด

เปิด `/allocations`

เลือกคำขอ **ข้าวสารฮาลาล ของศูนย์พักพิงวัดคลองแห**

**ชี้ให้ดู** ระบบเสนอเฉพาะล็อตที่จ่ายได้จริง คือหมวดตรงกัน ยังไม่หมดอายุ
และข้อกำหนดด้านอาหารตรงกัน เรียงล็อตที่ใกล้หมดอายุขึ้นก่อน

**พูดว่า** การเรียงแบบนี้เรียกว่า FEFO คือของที่จะหมดอายุก่อนต้องถูกจ่ายออกก่อน
เพื่อลดของเสีย

ใส่จำนวน แล้วกดจัดสรร → **กล่องยืนยันเด้งขึ้น**

**พูดถึงกล่องยืนยัน** นี่คือ Web Component ที่เลือกอธิบายในรายงาน
ใช้ `<dialog>` มาตรฐานของ HTML ไม่ได้ใช้ library ภายนอก
เหตุผลที่ต้องมีคือการตัดจ่ายย้อนกลับยาก ต้องให้ผู้ใช้หยุดอ่านสรุปก่อนกด

กดยืนยัน → ยอดคลังลดลง คำขอเปลี่ยนสถานะเป็นจ่ายบางส่วนหรือจ่ายครบ

### 2.8 โชว์ว่าระบบปฏิเสธอะไรบ้าง ← จุดขายของงาน

ลองทำสิ่งที่ผิดให้อาจารย์ดู อย่างน้อย 1 อย่าง

| ลองทำ | ระบบจะ |
|---|---|
| จ่ายเกินจำนวนที่มีในล็อต | ปฏิเสธ บอกว่าของไม่พอ |
| เลือกคำขอฮาลาล แล้วหาล็อตทั่วไป | ไม่ขึ้นในรายการให้เลือกตั้งแต่แรก |
| จ่ายเกินจำนวนที่ขอ | ปฏิเสธ |

**พูดว่า** กฎพวกนี้ไม่ได้อยู่แค่ในหน้าเว็บ แต่เขียนไว้ในฐานข้อมูล
ต่อให้ส่งคำสั่งตรงเข้าฐานข้อมูลโดยไม่ผ่านหน้าเว็บก็ยังถูกปฏิเสธ
ทีมทดสอบเรื่องนี้ไว้ 17 กรณี อยู่ในรายงานหัวข้อที่ 8

### 2.9 ประวัติการจัดสรร

เปิด `/allocations/history`

**ชี้ให้ดู** บันทึกว่าใครจ่าย เมื่อไหร่ จำนวนเท่าไร จากล็อตไหน ไปศูนย์ไหน
และมีใบส่งมอบที่พิมพ์ได้

## ฉากที่ 3 — อาสาสมัคร

> สลับไปหน้าต่างที่ล็อกอิน `volunteerTest` ไว้แล้ว

เปิด `/volunteer`

**ชี้ให้ดู** ของที่เพิ่งจัดสรรไปเมื่อกี้ โผล่ในกล่อง "ของที่กำลังส่งมาศูนย์คุณ" แล้ว

**พูดว่า** อาสาสมัครเห็นเฉพาะงานของศูนย์ตัวเอง เข้าหน้าคลังหรือหน้าจัดสรรไม่ได้เลย
ลองพิมพ์ `/inventory` ที่ช่อง URL ให้ดู → ระบบเด้งกลับทันที

กด **ยืนยันรับของ** ใส่จำนวนที่ได้รับจริง

**พูดว่า** ระบบให้กรอกยอดที่รับจริงแยกจากยอดที่ส่งมา เพราะของอาจตกหล่นระหว่างทาง
ถ้าบังคับให้ตรงกันเสมอ ตัวเลขในระบบจะสวยแต่ไม่จริง

**ชี้ให้ดู** การ์ดรูปยืนยันตัวตนด้านล่าง อาสาสมัครอัปโหลดรูปตอนสมัครแล้วดูได้ที่นี่

## ฉากที่ 4 — ผู้ดูแลระบบ

> กลับไปหน้าต่าง `adminTest`

เปิด `/admin/centers`

**ชี้ให้ดู**
- เพิ่ม แก้ไข และปิดใช้งานศูนย์
- รายชื่อผู้ใช้ทั้งหมด แยกตามบทบาท
- เปลี่ยนบทบาทและศูนย์ที่สังกัดได้

**พูดว่า** คนที่สมัครเข้ามาใหม่จะเป็นอาสาสมัครเสมอ ถ้าจะให้เป็นเจ้าหน้าที่
ต้องให้ผู้ดูแลเลื่อนขั้นให้ที่หน้านี้ ไม่มีทางสมัครเป็นเจ้าหน้าที่เองได้

## ความเสี่ยง อ่านก่อนวันนำเสนอ

### ถ้าจะสาธิตสมัครสมาชิกสด ต้องปิดการยืนยันอีเมลก่อน

ตอนนี้สมัครเสร็จยังล็อกอินไม่ได้ ต้องกดลิงก์ยืนยันในอีเมลก่อน
และ Supabase แผนฟรีจำกัดจำนวนอีเมลต่อชั่วโมง ถ้าวันนั้นส่งไปหลายรอบแล้ว
เมลอาจไม่มา จะดูเหมือนระบบพังทั้งที่ไม่ได้พัง

```
Supabase → Authentication → Sign In / Providers → Email → ปิด Confirm email
```

ปิดแล้วสมัครเสร็จล็อกอินได้ทันที

### เตรียมบัญชีสำรองไว้

ถ้า `adminTest` หรือ `volunteerTest` มีปัญหา ยังมีบัญชีอื่นในบทบาทเดียวกัน

```
admin      adminTest, chalisa, chitakan, kitthakarn, M3enSan, Meen, Sareeya
staff      staffTest
volunteer  volunteerTest, volunteam, nteam
```

### ถ้าอาจารย์ถามเรื่องสิทธิ์ ให้ตอบแบบนี้

ทีมทดสอบจริงแล้ว ระบบ **แยกสิทธิ์การดูกับการแก้ไขออกจากกัน**

| | เจ้าหน้าที่ทำได้แค่ไหน |
|---|---|
| ดูข้อมูล | ดูยอดคลังทุกศูนย์ได้ |
| เพิ่ม แก้ไข ลบ | เฉพาะศูนย์ที่ตัวเองสังกัด |

**เหตุผลที่ดูข้ามศูนย์ได้** ศูนย์พักพิงไม่มีของเป็นของตัวเอง ต้องเห็นว่าคลังของศูนย์อื่น
เหลืออะไร จึงจะเลือกมาจัดสรรได้ ถ้าปิดการมองข้ามศูนย์ ฟีเจอร์จัดสรรจะใช้ไม่ได้เลย

**ข้อจำกัดการแก้ไขบังคับที่ฐานข้อมูลจริง** ทีมพิสูจน์ด้วยการสวมสิทธิ์เจ้าหน้าที่แล้วยิงคำสั่ง
ตรงเข้าฐานข้อมูล ผลคือแก้ล็อตของศูนย์อื่นไม่มีแถวใดถูกเปลี่ยน และสร้างล็อตให้ศูนย์อื่น
ถูกปฏิเสธด้วยข้อความว่าขัดกับกฎสิทธิ์ระดับแถว

### `staffTest` สังกัดศูนย์พักพิง

เปิดหน้าคลังได้ปกติและเห็นของครบทุกศูนย์ แต่หัวข้อจะเขียนว่า "ศูนย์ของคุณ: ศูนย์พักพิงวัดคลองแห"
ซึ่งเป็นศูนย์ที่ไม่มีของเลย ถ้าอาจารย์สังเกตเห็นความไม่ตรงกันตรงนี้ ให้อธิบายตามตารางข้างบน

### ถ้าอินเทอร์เน็ตมีปัญหา

เปิด localhost สำรองไว้ก่อนเริ่ม โดยรัน `npm run dev` ทิ้งไว้
ใช้ฐานข้อมูลตัวเดียวกัน ข้อมูลตรงกันทุกอย่าง

## ลำดับสั้น ๆ สำหรับจำ

```
ไม่ล็อกอิน    หน้าแรก → แจ้งบริจาค → ขอความช่วยเหลือ → สมัครอาสา
ผู้ดูแล       สรุปภาพรวม → อนุมัติคำร้องบริจาค → ใบรับของ → ทะเบียนผู้บริจาค
              → อนุมัติคำขอ → คลัง → จัดสรร → โชว์การปฏิเสธ → ประวัติ
อาสาสมัคร     ยืนยันรับของ → โชว์ว่าเข้าหน้าคลังไม่ได้
ผู้ดูแล       จัดการศูนย์และผู้ใช้
ปิดท้าย       สลับภาษา + โหมดมืด
```
