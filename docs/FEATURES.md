## วิธีตรวจว่าใครทำอะไร

### วิธีที่ 1 — ดูจาก Pull Request (แนะนำ)

ทุกงานเข้า `main` ผ่าน PR ทั้งหมด **30 PR** แต่ละอันมีคนเขียน รายการไฟล์
และคำอธิบายว่าแก้อะไรทำไม

> https://github.com/Agent00PED/disaster-relief/pulls?q=is%3Apr+is%3Amerged

**ข้อควรรู้:** บาง PR ขึ้นชื่อผู้เปิดเป็น `Agent00PED` ทั้งที่เนื้องานเป็นของคนอื่น
เพราะตอนรีวิวมีการแก้เพิ่มแล้วเปิด PR ให้ ถ้าจะดูว่าใครเขียนโค้ดจริง
ให้เปิดแท็บ **Commits** ในตัว PR นั้น จะเห็นชื่อผู้เขียนของแต่ละ commit

### วิธีที่ 2 — นับจาก git โดยตรง

ดูว่าใครแก้ไฟล์ในโฟลเดอร์ไหนบ้าง

```bash
git log --no-merges --format='%an' -- app/inventory | sort | uniq -c | sort -rn
```

เปลี่ยน `app/inventory` เป็นโฟลเดอร์ของฟีเจอร์ที่อยากดู (ดูจากตารางข้างบน)

ดู commit ของคนคนเดียว

```bash
git log --no-merges --author=chitakan --oneline
```

ดูสรุปทั้งทีม

```bash
git shortlog -sn --no-merges main
```

### วิธีที่ 3 — เปิด branch ตามชื่อฟีเจอร์

branch `F1-…` ถึง `F6-…` เป็นจุดอ้างอิงของแต่ละฟีเจอร์
ชี้ไปที่ commit ที่งานฟีเจอร์นั้นเสร็จสมบูรณ์

```bash
git log F3-inventory --no-merges --author=Ratthanan --oneline
```

แต่ละ branch ชี้ไปที่ commit ที่งานของฟีเจอร์นั้นลงครบแล้ว

| branch | ชี้ไปที่ | งานของเจ้าของฟีเจอร์ |
|---|---|---|
| `F1-accounts-centers` | merge ของ PR #45 | 13 commit |
| `F2-donations-intake` | merge ของ PR #56 | 16 commit |
| `F3-inventory` | merge ของ PR #44 | 6 commit |
| `F4-requests` | merge ของ PR #53 | 6 commit |
| `F5-allocations` | merge ของ PR #41 | 22 commit |
| `F6-donors` | merge ของ PR #48 | 4 commit |

ตรวจแล้วว่าไม่มี commit ที่แตะโฟลเดอร์ของฟีเจอร์ไหนหลุดออกไปอยู่นอก branch ของตัวเอง

**ข้อจำกัดที่ควรรู้:** งานทุกฟีเจอร์ merge เข้า `main` หมดแล้ว
branch พวกนี้จึงเป็น "ป้ายบอกตำแหน่ง" ในประวัติเดียวกัน ไม่ได้แยกโค้ดออกจากกัน
เปิด branch ไหนก็เห็นทั้งโปรเจกต์ ถ้าอยากดูเฉพาะงานของคนใดคนหนึ่ง
ให้ใช้วิธีที่ 1 หรือ 2 จะตรงกว่า

### เลข Behind / Ahead ในหน้า Branches หมายถึงอะไร

    Behind   main มี commit ที่ branch นี้ยังไม่มี กี่อัน
    Ahead    branch นี้มี commit ที่ main ยังไม่มี กี่อัน

ทั้ง 6 branch ขึ้น **Ahead = 0** ซึ่งเป็นสิ่งที่ต้องการ
แปลว่าไม่มีงานค้างอยู่นอก `main` เลย ทุกอย่างเข้าเส้นหลักหมดแล้ว

ส่วน **Behind** ต่างกันไปตามว่าฟีเจอร์นั้นเสร็จตอนไหน
เช่น F5 เสร็จก่อนใครเพื่อน ตัวเลข Behind จึงเยอะ
เพราะหลังจากนั้นเพื่อนคนอื่นยัง merge งานเข้า `main` อีกหลายรอบ

เลข Behind เยอะไม่ได้แปลว่างานเก่าหรือมีปัญหา และไม่ต้องไปตามอัปเดตให้เท่ากับ main
เพราะ branch พวกนี้ตั้งใจให้เป็นจุดอ้างอิงย้อนหลัง ไม่ใช่ branch ที่ยังทำงานอยู่

## ตัวเลขจริงจาก git

นับ commit ที่ไม่ใช่ merge commit แยกตามโฟลเดอร์ของแต่ละฟีเจอร์

| ฟีเจอร์ | ผู้รับผิดชอบ | commit ของเจ้าของฟีเจอร์ |
|---|---|---|
| F1 | ทีม (`kitthakarn`) | 13 |
| F2 | ชมพู่ (`chalisa1103`) | 15 |
| F3 | มีน (`Ratthanan-Yidnorradin`) | 6 |
| F4 | ฟี่ (`0858819875za-sudo` + `sareeya0902`) | 6 |
| F5 | ฮัม (`Agent00PED`) | 22 |
| F6 | ดาว (`chitakan0762548-hub`) | 4 |

ตัวเลขนี้ไม่ได้นับงานส่วนกลาง (คำแปล หน่วยของ กฎฐานข้อมูล) และไม่ได้นับ
commit ที่เข้าไปช่วยแก้ข้ามฟีเจอร์กัน จึงใช้ดูภาพรวมได้ แต่ไม่ใช่ตัวชี้วัดปริมาณงาน

## หมายเหตุเรื่องหน้า Contributors ของ GitHub

หน้า Contributors อาจแสดงจำนวน commit ของบางคนไม่ตรงกับความจริง
เพราะ GitHub ผูก commit เข้ากับบัญชีด้วย **อีเมล** ถ้าอีเมลที่ตั้งไว้ใน git
ไม่ตรงกับอีเมลที่ลงทะเบียนในบัญชี GitHub commit นั้นจะไม่ถูกนับให้

ถ้าตัวเลขบนหน้าเว็บดูไม่ตรง ให้ใช้คำสั่ง git ในวิธีที่ 2 แทน
ซึ่งอ่านจากประวัติจริงในไฟล์ repo ไม่ได้ขึ้นกับการตั้งค่าบัญชี
